# H=45% 对冲端配置计划

> **状态**：R4 / P=25% / H=45% / C=30%
> **最后更新**：2026-06-20
> **关联**：`risk_os_state_machine.py` → `event_state.json` → `read_ssot_position()` → 本计划

---

## 背景

SSoT 单向流切换合龙后，系统权威输出 R4 防御档，要求 **H=45%** 对冲。当前实配：
- P（主仓）≈ 2.26%，远在 25% 上限以下 → 不构成约束，R4 对你是天花板不是砍仓指令
- H（对冲）≈ 0% → **这是 gap**
- C ≈ 98%，已是 SGOV（全部在主账户）→ H 建仓 = SGOV→BIL 换仓，非闲置资金入场

R4 的指令不是"减仓"，是"把弹药准备好"。因为 R4 判断 A 端流动性压力到了闪断概率不可忽视的级别——你要的不是躲避下跌，是闪断发生时手里有不跌的钱、联储进场后能抄底。

---

## 1. 标的敲定

> ✅ **已确认**：美股券商 = **IBKR**，单账户。不支持外部货基（VMFXX 不可用），无子账户隔离。
> 隔离靠**不同 ticker 视觉区分**（BIL vs SGOV），非物理隔离。这是单账户约束下的最优解。

### 标的方案（已锁定 — IBKR 单账户）

| 仓位 | 标的 | 理由 |
|------|------|------|
| **H (45%)** | **BIL**（SPDR Bloomberg 1-3 Month T-Bill ETF） | 用 ticker 名区分：看到 BIL = 弹药，不动。ER 0.1356% |
| **C (30%)** | **SGOV**（iShares 0-3 Month Treasury Bond ETF） | 看到 SGOV = 应急金，可调用。ER 0.09% |

**隔离机制**：单账户内靠 ticker 名视觉区分。BIL 和 SGOV 同屏但不同行——比纯靠脑子防火墙强（不会面对一个 SGOV 大 blob 去心算哪部分能卖），但不是硬物理隔离。压力时刻你仍可能手滑卖 BIL，没有物理阻碍。

这是单账户约束下的最优解。要更强的隔离，等于要开第二个账户——那个决策和成本你自己判断。

### 核心设计原则

用物理隔离（不同账户）替代心理防火墙。不靠脑子记住"这笔是弹药不能动"。

> ⚠️ **防止收益诱惑**：BIL 和 SGOV 存在 ~4.5bp ER 差异（BIL 略贵），不要为几个 bp 把 H 和 C 合并到同标的同账户——隔离的价值（压力时刻不手滑）远超几个 bp。

## 2. H/C 区分

| | H (45%) | C (30%) |
|---|---|---|
| 标的 | BIL（子账户） | SGOV（主账户） |
| 性质 | 冻结弹药，触发前不动 | 灵活储备，可应急可抄底 |
| 触发条件 | 系统降档 或 闪断后联储进场（见 §5） | 随时可由主观调用 |
| 预期收益 | ~Fed Funds − 13.5bp ER | ~Fed Funds − 9bp ER |
| 标的间 ER 差 | ~4.5bp/年（BIL vs SGOV） | — | ← 无关紧要，不是 H 的真实成本 |

**H 的真实机会成本**：这 45% 没去参与 P（AI 链）的上行。R4 的全部逻辑就是"现在不该让这笔钱去冒险"——所以这个机会成本是主动选择承担的，不是被忽略的。标的之间的几个 bp ER 差异是噪声，真正的大数是"AI 行情来时你在岸上"。

实物上都是短债/类现金，但物理隔离保证了在压力时刻你不会混淆"能不能动"。

## 3. 分批节奏

### 原则

- **增量配置**：主仓 2.26% 远低于 P=25% 上限，不涉及砍仓
- **H 是 regime 的函数**，不是一次性锁死的静态仓位：
  - R4 → H 目标 45%
  - R3 → H 目标 35%
  - R2 → H 目标 25%
  - R1 → H 目标 15%
- 分批让实配追随目标，regime 变化时不用大进大出

### 建议节奏

| 批次 | 时点 | 目标 | 占 H 总目标 |
|------|------|------|------------|
| 第 1 批 | 立即 | **20%** — 可配现金 98%，不受钱约束；短债可逆性高，等的不是点位 | ~44% |
| 第 2 批 | 第 1 批后 3-5 个交易日，确认清单逐项通过 | 35% | ~78% |
| 第 3 批 | regime 维持 R4 ≥ N 日后（N 自定，建议 5-10 个交易日） | 45% | 100% |

**实物状态**：C 的 98% 已经是 SGOV。H 建仓 = **卖 SGOV → 买 BIL**（同一账户内），短债换短债，零价格风险，无择时问题。

**第 1 批 20% 的操作**：卖 20% SGOV → 买 20% BIL。同一账户，30 秒下单。

**第 1 批 20% 的逻辑**：
- 短债换短债，无价格损失，等的不是点位是确信度
- 20% = 弹药近半到位，同时留 5 个交易日确认窗口
- 如果 R4 很快降档 → 只转了 20% 而非 45%，还原轻松
- 如果 R4 持续 → 3 批走完约 2-3 周到满仓 45%

**节奏不绑定时点**：绑的是"确认"。每批之后用确认清单逐项检查——不是"感觉对"，是逐项核对（见下方）。如果 regime 在分批过程中降档了，目标自动下调，停止建 H。

### 每批间确认清单（逐项核对，不是"感觉对"）

每批建完、下一批前，检查以下五项，全部 ✅ 才推下一批：

- [ ] **regime 仍是 R4** — 检查 `event_state.json` 或 dashboard regime 行；若已降档 → 目标自动下调，重算剩余批次
- [ ] **A 端信号仍支持防御** — EFFR-IORB 仍🟠/🔴、ON RRP 仍低位、bear-flatten 仍在（至少两项）若 A 端信号消退 → 重新评估 R4 是否还成立
- [ ] **SSoT 横幅没报异常** — 无 fallback 标记、无数据降级横幅；若 SSoT 降级 → 数据质量存疑，暂缓推进
- [ ] **cooling 仍 <2/3 且 DFII10 仍 >2%** — 若 cooling 累积≥2/3 或 DFII10 破 2% → TLT 进场逻辑激活（§4），H 计划要和 TLT 仓位协调，不是无脑继续建 H；停下来重新评估整体仓位结构
- [ ] **剧本 1（缩圈/AIcapex）判断未动摇** — 你对"高真实利率 + 缩圈"的核心判断还在；若动摇 → 整个 P/H 结构可能需要重新考虑

### 降档时的回收

如果 regime 从 R4→R3：
- H 目标从 45% → 35%
- 多出的 10pp 从 BIL 卖出 → 去路由你决定（回 C 或进 P）
- 不叫"减仓"，叫"弹药回收重新分配"

## 4. TLT 归属（关键边界）

### 结论：R4 下 TLT = 零仓位，不进 H，不进 P

**原因**：
- P 里装的 AI 链（NVDA/AVGO/MU...）赌的是"高真实利率 + 缩圈"（剧本 1）
- TLT 赌的是"真实利率退潮 + cooling"（剧本 2 前兆）
- 两者赌相反利率情景；把 TLT 放进 P 会在同一篮子内部互相对冲——付两份仓位成本，净敞口被自己抵消
- 放进 H 更不对——H 是纯防御弹药，要求"闪断时不缩水"，TLT 久期 ~17 年在真实利率上升时可跌 10%+

### TLT 是独立触发仓位

| 属性 | 值 |
|------|-----|
| 当前仓位 | **零** |
| 触发条件 | **Nowcast cooling 累积 ≥ 2/3** 且 **DFII10 破 2.0%** |
| 触发后性质 | "真实利率退潮"顺势仓位，不是 hedge、不是对赌 |
| 触发后大小 | ≤ 触发时 P 仓位的 20-30%（随主仓浮动，非固定数） |
| 何时再退出 | cooling 中断、regime 回升至 R4+、或 DFII10 回升破 2.5% |

**设计意图**：TLT 不是"需要纠结每天看"的仓位，是等信号自动触发。触发条件明确后，它从纠结项变成监控项——跟你给 2s10s、cooling 设的监控一个套路。

## 5. H 解冻条件

H 的全部价值在于"行权时刻"用对。不是涨了就该解冻。

### 可以解冻（H → P 或 H → C）

| 触发 | 操作 | 逻辑 |
|------|------|------|
| **regime 降档**（R4→R3） | H 目标 45%→35%，多出的 10pp 解冻 | 防御需求下降，弹药回收 |
| **regime 降档**（R4→R2 或更低） | 同上，按 regime 阶梯回收 | 系统性压力解除 |
| **A 端闪断确认 + 美联储进场** | H 全部/大部分解冻，低位加 P（AI 链） | **这是你美联储 put 假设的执行时刻**——危机里手里有 45% 不跌的弹药，联储一进场你在低位把 AI 加回来 |

### 不解冻

| 场景 | 原因 |
|------|------|
| P 端涨了、想追 | 这不叫解冻，叫追涨——违背 H=防御弹药的定位 |
| cooling 信号来但没累积够 | TLT 是独立触发仓位（§4），不要从 H 里挪用 |
| R4 维持、无闪断 | 保持 H=45%，弹药就是为这个局面准备的 |

### 一句话纪律

> **H 不是闲置现金，是美联储 put 的执行工具。行权条件 = 系统降档 或 联储进场——缺一不可。**

## 6. 跟踪

### 诚实原则：Dashboard 不显示它不知道的数

Dashboard 是宏观信号系统，不连接你的券商账户。它**可以**自动显示：
- **H 目标**（regime → 查表：R4=45%, R3=35%, R2=25%, R1=15%）
- **C 目标**（固定 30%）
- **regime 当前状态**

它**不能**自动显示：H 实配、C 实配。如果让 dashboard 显示这些数而不标来源，就是 silent source——和你审计反复抓的同源 bug。

### Dashboard 应显示

```
H 目标：          45%（当前 R4）
C 目标：          30%
H 实配（手动）：  [你手动更新，附最后更新日期]
C 实配（手动）：  [你手动更新，附最后更新日期]
偏离（H）：       [实配 − 目标] pp ｜ 绿灯/黄灯/红灯
```

实配行标注 `最后更新于 YYYY-MM-DD`，让陈旧性可见。

### 你自己跟踪（不在 Dashboard）

- H 实配从券商账户拉，用你的记账系统（Excel/脚本/券商截图）维护
- 不要依赖 dashboard 告诉你实配——它是信号系统，不是组合管理系统

### 阈值建议

| 偏离度（|实配-目标|） | 信号 | 含义 |
|---------------------|------|------|
| ≤ 3pp | 绿灯 | 到位 |
| 3-8pp | 黄灯 | 在建，有节奏地在追 |
| > 8pp | 红灯 | 弹药缺口，标警 |

当前 H 缺口 ≈ 45pp → **红灯**，这是你系统合龙后最大的未对齐项。

### TLT 监控（独立一行，Dashboard 可自动显示）

```
TLT 触发监控：cooling 累积 [X/3] | DFII10 [Y.Y%]
触发状态：  未触发 / 已触发-待执行 / 已执行
```
TLT 触发条件是纯信号值，dashboard 可以直接读（cooling 来自 nowcast，DFII10 来自 FRED），不涉及手动输入。
