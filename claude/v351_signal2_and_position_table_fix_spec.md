## §1 Fix 1：Signal #2 修正（paper_trade_v35.py 第 55-56 行）

**当前代码（已确认错误，非笔误，7/1 第一版起就是这样）：**
```python
signals["HYG_5d_pct"] = round(hyg_5d, 1) if hyg_5d else None
signals["HYG_trigger"] = hyg_5d < -1.5 if hyg_5d else False
```

**改为：**
```python
hy_oas_5d_delta_bp = n_day_chg("BAMLH0A0HYM2", 5)
signals["HY_OAS_5d_delta_bp"] = round(hy_oas_5d_delta_bp, 1) if hy_oas_5d_delta_bp is not None else None
signals["HY_OAS_5d_trigger"] = (hy_oas_5d_delta_bp > 15) if hy_oas_5d_delta_bp is not None else False
```

**三处必须确认，不能假设对：**

1. **方向不是简单复制运算符。** 旧逻辑是 `hyg_5d < -1.5`（HYG 价格是资产价格，下跌=压力）。新逻辑必须是 `hy_oas_5d_delta_bp > 15`（HY OAS 是利差，走阔=压力），符号方向相反。如果照抄 `<` 会产生一个新 bug，而且比现在这个更隐蔽——单位和方向都换了名字却还是错的。
2. **单位要单独核实。** `BAMLH0A0HYM2` 在 FRED 上通常以百分点存储（如 2.75 = 275bp）。`n_day_chg()` 返回的是百分点变化还是已转换成 bp，要在改之前打印出来看一眼原始返回值，不能假设。这跟 ABCDS 那次 KCB `near_atm_iv` 小数被当百分比处理、级联出假 regime 和假信号，是同一类错误——单位不核实，符号和逻辑再对也没用。
3. **字段名要跟着改，不只是数值。** `HYG_5d_pct` / `HYG_trigger` 这两个名字本身就是这次 bug 两天没被发现的部分原因——名字和它实际算的东西对不上,人扫一眼代码不会起疑。改成 `HY_OAS_5d_delta_bp` / `HY_OAS_5d_trigger`，让字段名如实描述内容。

### 关键要求：停止计算，不只是停止渲染

SSoT Orchestrator 的仓位计算逻辑（无论在哪个函数/模块里）要从 daily/dashboard 生成流程里**整条摘除调用**，不是保留计算、只在模板层不渲染。如果这个函数出于其他原因必须留在代码库里，函数名加前缀标注（如 `DEPRECATED_TIER3_ssot_position_sizing`），防止以后哪次改动又把它接回渲染链路——这正是这次的教训：声明"永久禁入"和代码"真的调用不到"是两件事，中间那道连接必须是硬的（函数摘除/改名），不能只是文档里写了不用。

### §3.1 开放问题（不在本次必须处理范围，留给你决定）

"R4 防御"这个 regime 标签本身，是跟 P/H/C 同一台 Orchestrator 机器算出来的（§37 原话："Risk OS SSoT v1.0 + Orchestrator v2.0（R1-R4 Regime + 双探针互锁）"是治理违规入口）。一个不熟悉背景的人看到"R4 防御"，大概率也会读成"该防御了"，跟看到"P=25%"没有本质区别。

两个选项，都合理，取决于你要不要保留 regime 分类这层：
- **选项 A**：R1-R4 标签跟 P/H/C 一起整体退役，daily/dashboard 只保留 CASC/VTS/RCV/2s10s/RYS 这些已经是纯诊断的 overlay，不再有任何"综合判定"式的单一标签。
- **选项 B**：保留 R1-R4 作为纯描述性的"跨域信号计数"标签（类似"今天几个域亮红灯"），但要在文档里显著位置标注"regime 标签仅描述当前信号计数分布，不是仓位建议，不经过 Tier 2 验证"，且不能再出现在同一行/同一句里和 P/H/C 绑在一起。

这个不算 bug，是设计决定，我不替你选。
